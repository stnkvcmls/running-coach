Running Coach · second opinion · UI/UX

It looks good now. It doesn’t yet tell the truth consistently.

The effort-colour redesign made the app readable. What remains are problems of trust (the same run gets two adherence numbers, Today can show a session from a superseded plan), of coherence (four readiness signals that disagree), and of length (Today is almost three phone screens). These are screenshots of the real app running on the seeded three-year dataset, annotated with the findings both reviewers agreed on.

  1. 1

    Readiness 55 is “Good” while its own line says HRV is holding it back Medium · N2

    The 0–100 score re-weights Garmin’s sleep score, body battery and stress (which already include HRV), adds HRV again, then adds 100 − ATL. That last term marks a fit runner as fatigued every day (High · S1).

    Fix: one verdict (“Train as planned / Ease off / Rest”) and the reasons under it. Compute fatigue from TSB, not absolute ATL.

  2. 2

    “61% adherence”: the run’s own page says 100% High · N1

    Today scores the run against reps that workout_translator invented for the plan day; the detail page scores it against Garmin’s scheduled workout. All six reps landed within 5 s, and the headline still says 61%.

    Fix: one definition, computed once and stored on the activity. Say what happened (“6/6 reps on target”) instead of giving a percentage.

  3. 3

    The RPE tap deletes the coach’s analysis and pays for a new one High · U2

    The 1–10 row posts to /feedback, which wipes the insight and re-queues an LLM job. If the run was never rated, it also sends rating:"good", so after RPE 10 the model is told the run “went well”. Tapping 7 then 8 pays for two analyses.

    Fix: a separate RPE endpoint that only updates training load. Run one analysis per run, after sync.

  4. 4

    “How do you feel this morning?” at 18:30, under a second survey Medium · N8

    Two surveys back to back, with opposite polarity: RPE 1 = easy, soreness 1 = very sore. That is three 5-button rows and one 10-button row on a single screen.

    Fix: make Today time-aware. Show the check-in before the run (one row: legs fresh / ok / sore) and the RPE only after it.

  5. 5

    Body panel repeats Progress, and its “Daily history” link opens a single day High · U3

    The link goes to /daily/{id}, not the history. The four tiles duplicate the Progress tab.

    Fix: a single line on Today (“Sleep below your range 2 nights”) with the full tiles left to Progress.

  6. 6

    “Very fresh, +17” sits two cards below “holding you back” Medium · N2

    Form (TSB) is a fourth readiness signal, worded in a way that contradicts the first one.

    Fix: feed TSB into the single verdict; keep the Fitness/Fatigue chart on Progress.

  7. 7

    Races and coach notes sit below the fold, after everything else High · U1

    Today mixes a session, two surveys, a body panel, a form chart, a race list and a notes feed. The coaching (briefing → recap) is split between a link in the hero and a feed at the bottom.

    Fix: Today = verdict, session, one question, one coach note. Everything else goes to Plan or Progress.

Today, one plan regeneration later Critical · A2

Reproduced in the running app: a newer plan was added (as the Sunday job does every week), and Wednesday changed to rest. The week strip, which reads the latest plan, shows rest. The hero, which /today fed an older plan day, shows “Easy” with nothing in it.

1 2 3
  1. 1

    The week strip shows Wednesday as rest (latest plan)

    It reads /training-plan, which orders by generated_at desc.

  2. 2

    The hero says “Easy · Easy” (old plan)

    /today runs (user_id, day_date).first() with no plan scope and returns plan day 3 from the old plan. Old days are never deleted when a plan regenerates.

  3. 3

    Distance, time and pace are all blank

    TodayHero looks up id 3 among the latest plan’s days, doesn’t find it, and renders an empty card. The morning adaptation push and the pre-workout briefing target the same stale day.

    Fix: one get_active_plan_day() helper scoped to the latest plan, or delete superseded future days on regeneration.

    The coach line exists only if you rated the run High · U2

    Automatic post-run analysis was removed in March (c26d2ea); the README and CURRENT_STATE.md still promise it. The rating or RPE tap is now the only trigger, and each tap replaces the analysis.

  2. 2

    “100% adherence” (Today said 61%) High · N1

    This one is scored against Garmin’s scheduled steps; Today’s is scored against synthetic ones.

  3. 3

    Chart tabs clip at 390 px (“Powe”) Low

    The overflow has no affordance showing that more tabs exist. Running dynamics are tucked behind it.

  4. 4

    Pace time-in-zone is shown to the second but computed from ~200 sampled points Medium · N3

    The browser counts point-decimated instantaneous speeds (metrics[::step]) and assumes even spacing, which Garmin smart recording and auto-pause break. (The 0:00 in Z3–Z5 here comes from the seed’s flat pace stream; the method is wrong regardless.)

    Fix: compute it server-side on the full, time-aligned stream in streams.py, and show rounded minutes.

What works: keep it

Progress → Body is the best screen in the app

One metric per row, the value in large tabular type, a plain-language status (“Below your range for 2 nights”), and a grey band showing the runner’s own normal range. No colour noise. This is the template for how Today should talk about recovery.

The session hero

“6 × 800 m” in display type, the reps as bars, one primary action. The problems on Today are the things around it, not the hero itself.

The visual system

Effort-only colour, ink actions, Archivo with tabular numerals, and calm light and dark themes. The direction approved in UI_UX_CRITIQUE.md §5 worked. Don’t start another visual redesign: the remaining problems are not visual.

Two states instead of one long page. One verdict instead of four signals. One question at a time. One coach voice. The examples use the same seeded athlete and day.

Rules behind the mock-ups

1. Today has two states (before and after the run), and each fits in about one screen.
2. One readiness verdict with reasons; the raw tiles live on Progress.
3. One question at a time, with consistent polarity (higher = harder or better).
4. Describe adherence as facts (“6/6 reps”); show no second percentage.
5. Every action button has a text label; show only the actions that can actually work.

Not a visual redesign

Same tokens, type and components. These changes remove and merge things and fix the data behind them. Estimate: Today about 2 days, Plan about 1 day, once the backend fixes (A2, N1, U2, G4) land.
